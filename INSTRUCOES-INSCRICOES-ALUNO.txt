DEPPI-WEB — inscrições do aluno integradas à API publicada

O que foi atualizado:
- A tela “Minhas inscrições” agora consulta GET /inscricoes/minhas.
- A listagem usa os dados reais retornados pela API: curso, instituição/campus, data, situação e documentos enviados.
- Foram mantidos filtros por situação, busca, layout responsivo e modal de detalhes.
- A tela apresenta estados de carregamento, erro com opção de tentar novamente e estado vazio quando o aluno ainda não possui inscrições.
- O modal de confirmação do curso continua usando POST /inscricoes.
- O menu do aluno e a tela administrativa de inscrições foram preservados.

Compatibilidade confirmada por inspeção do código da API enviada:
- A rota GET /inscricoes/minhas está registrada antes do middleware de permissão administrativa.
- A rota exige autenticação e retorna { mensagem, inscricoes }.
- Cada inscrição inclui status, data, dados do curso, instituição e documentos.

Configuração:
- O front-end usa NEXT_PUBLIC_API_URL quando definida.
- Sem essa variável, usa a URL padrão já configurada em src/lib/api.ts.
- Se a API publicada estiver em outro endereço, configurar NEXT_PUBLIC_API_URL no ambiente de deploy do front-end.

Teste recomendado antes de publicar:
1. npm ci
2. npm run build
3. Entrar com uma conta ALUNO.
4. Abrir “Minhas inscrições” e confirmar que a resposta de GET /inscricoes/minhas é exibida.
5. Fazer uma inscrição em um curso e voltar à listagem.
6. Entrar com perfil DEPPI e confirmar que o painel administrativo continua funcionando.

Observação: a validação de build não foi concluída neste ambiente porque o executável Next.js não estava disponível em node_modules. Executar os comandos acima em ambiente com dependências instaladas antes do deploy.
